写 dualreceipt，为两本不能放进同一个数据库事务的离线合成安全台账设计协调器。一边记一次性钥匙的库存，一边记证物袋的交接。两边各自是程序新建的 SQLite 文件，可以单独重启。一次 transfer 必须在对业务读者可见的效果上同时消耗相应钥匙并交接一袋，第三份协调日志可用 SQLite，但读者可能直接启动另一进程，不能依赖进程内锁。一份请求可以在故障后重试；同请求 ID 同内容只能得到同回执，异内容冲突。对任一步骤结束后强制退出，恢复只允许最终全部提交或全部终止，且不允许已经返回成功的回执失效。
实现 apply、read、recover、audit。读者在恢复未完成时可以得到明确 pending，但不得把库存或持有人任一边的半成品当成已提交状态；以当前会话逻辑时间支持从旧快照复核。audit 输出某个回执对应的最小持久证据和非法状态，如果两本账的持久顺序无法确定，不能随便造一个交接人。必须编写枚举至少六个已命名崩溃边界的测试，用独立子进程执行并用另一进程恢复，再加入两客户端争最后一把钥匙和两个请求各占不同资源而等待的场景；在合成小状态上将实际回执同串行线性化参考逐项对照。
从空仓库实现，使用 Windows 普通 CPU 和 Python 3.12 标准库，全部离线。交付 UTF-8 JSON CLI、明确的输入格式、README、合成夹具及 unittest。
